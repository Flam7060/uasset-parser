# Dino Storage v2 (1609138312): отчёт о багах и эксплойтах

_2026-10-25 · Skaqq_

## Сводка

Статический разбор Dino Storage v2 выявил девять проблем в серверных RPC: две высокого уровня, четыре среднего, три низкого. Схема везде одна: клиентские серверные события доверяют своим аргументам и полагаются на проверку в UI самого мода, поэтому модифицированный клиент, вызывающий эти события напрямую, обходит ограничения. На живом сервере ничего не проверялось.

- **Высокий — захардкоженный бэкдор по SteamID разработчика.** Литеральный SteamID `76561198056637517` вкомпилирован в `SoulTrapWeap_DS`, `SoulGunWeap_DS`, `SoulFinderWeap_DS` и `SoulTerminalStructure_DS` и даёт admin mode (бесплатный захват, трап диких и мёртвых дино, вытягивание душ из хранилища любого племени, admin soul recovery) на каждом сервере с этим модом — даже когда оператор выставил `DisableAdminMode=true`, и независимо от реального статуса админа.
- **Высокий — у `Starter Commit` нет проверки прав.** Любой игрок, способный открыть терминал, перезаписывает глобальный для сервера набор стартовых душ и уровень и чистит список выданных SteamID, переопределяя то, что получает каждый новый игрок.
- **Средний — `Set Bug Range` / `Set Newborn Range` не клампятся на сервере**, поэтому радиус зиппера/ловушки новорождённых можно задать далеко за пределами капа 1–50 / 1–15 из UI; **`Write Dino Bytes` пишет слот сейва с именем от клиента без проверки**; **`Recover Soul` / `Get Souls` работают с глобальным для сервера списком recovery, который сам RPC заново не авторизует**; **`Soul Options` снимает кастрацию дино в обход одностороннего латча UI.**
- **Низкий — `Add Custom Buff` грузит произвольный путь к ассету**, `Trade Soul` пропускает свою проверку команды, а косметические терминальные RPC действуют на последний использованный терминал без повторной проверки.

Находки, их влияние и предлагаемые исправления — ниже.

## Объём и метод

Обзор охватывает cooked-блюпринты Dino Storage v2 в том виде, как они ставятся из Steam Workshop (ID 1609138312, 180 файлов). Они разобраны офлайн утилитой uasset-parser, которая читает name map, экспорты и Kismet-байткод в псевдокод. На живом сервере ничего не запускалось.

Ассеты, прочитанные полностью или частично:

| Ассет | Роль | Разобран |
| --- | --- | --- |
| SoulTrap_DS | Предмет-душа: развёртывание, выпуск, загрузка, текст в инвентаре | Частично |
| SoulTrapWeap_DS | Оружие-ловушка: захват, данные души, статы родителей | Частично |
| DinoStorage2CCA | Компонент на игрока: действия терминала, recovery, офлайн-размножение | Частично |
| SoulTooltip_DS | Тултип: какие поля данных где показываются | Полностью |
| SoulGunWeap_DS, SoulGun_DS | Пушка душ | Частично |
| SoulTrapProj_DS, StatReplicatorBuff_DS | Снаряд, бафф статов | Частично / полностью |

Обзор искал четыре типа проблем: вызываемые клиентом серверные события, доверяющие своим аргументам; отсутствие проверок владельца или племени; логику, доверяющую данным, хранящимся на предмете; и правила развёртывания, загрузки или recovery, которые можно обойти.

## Находки

В каждой строке — ассет и функция, что сервер делает с вводом клиента и чего может добиться модифицированный клиент. Все они достижимы, потому что функция — это событие `NetServer` (или консольная / net-exec команда) на объекте, которым клиент владеет или на который ссылается, поэтому ограничения UI мода не применяются.

| # | Серьёзность | Ассет · функция | В чём проблема | Влияние на сервер |
| --- | --- | --- | --- | --- |
| 1 | Высокая | `SoulTrapWeap_DS` / `SoulGunWeap_DS` / `SoulFinderWeap_DS` / `SoulTerminalStructure_DS` — `Toggle Admin Mode`, `Login Admin Verify`, `Pull Souls`, `BPServerHandleNetExecCommand` | Захардкоженный SteamID `76561198056637517` принимается как админ. Проверка выполняется даже при `DisableAdminMode=true` (этот INI лишь уводит реальных админов на `IsPlayerAllowedToCheat`; ветка со SteamID вычисляется всегда). | У этого одного аккаунта постоянный admin mode на каждом сервере: бесплатный захват, трап диких и мёртвых дино, вытягивание душ из хранилища любого племени в радиусе и admin soul recovery — не отключается настройками. |
| 2 | Высокая | `SoulTerminalBuff_DS` — `Starter Commit` (Net·Server) | Нет проверки `IsPlayerAllowedToCheat`, команды или SteamID. Пишет `Starter ID`, `Starter Level`, чистит `Stored Starter IDs` и пересобирает `Starter Souls` на единственном глобальном акторе `DinoStorage2CCA` из аргументов клиента. | Любой игрок, способный дойти до терминала (то есть почти кто угодно), заменяет или стирает стартовые души, выдаваемые каждому новому игроку, задаёт произвольный `Starter Level` или чистит список выданных ID, чтобы игроки получали стартовые души повторно. |
| 3 | Средняя | `SoulTerminalBuff_DS` — `Set Bug Range`, `Set Newborn Range` (Net·Server) | Клиентский float `Range` используется напрямую (×300 для сферы перекрытия, ×38.25 для визуала) без клампа на сервере. Кап 1–50 / 1–15 есть только в `BugRangeMU_DS` / `NewbornRangeMU_DS`. | Модифицированный клиент задаёт огромный радиус на своём терминале: зиппер уничтожает всех диких дино, а ловушка новорождённых хватает детёнышей на очень большой площади, а `ServerOctreeOverlapActors` по такому радиусу каждый тик нагружает сервер. |
| 4 | Средняя | `SoulTerminalBuff_DS` — `Recover Soul`, `Get Souls` (Net·Server) | Обе работают с `DinoStorage2CCA.CCA Misc Data` — единым глобальным списком recovery, индексируемым клиентским `Dino Index`. Проверка прав (`AllowTribeGroupPermission`/команда/cheat/SteamID) живёт только в `BPServerHandleNetExecCommand` структуры, открывающем меню; сами RPC её не перепроверяют и не валидируют `Dino Index`. Записи в этот список попадают, когда прирученный дино с баффом `DeathAutoTrapBuff_DS` гибнет (death-auto-trap, с проверкой `BPIsTamed`) или когда душа создаётся/уничтожается (`Create Recovery File` в SoulGun/SoulTrap/терминале) — и список общий на всю карту. | Прямой вызов `Recover Soul` с произвольным индексом достаёт любую запись из общего пула, включая чужие: дино враждебного племени, погибший под death-auto-trap (или чья душа была уничтожена), оседает в общий recovery и может быть «воскрешён» — восстановлен в виде души в твой инвентарь, т.е. фактически украден. `Get Souls` целиком выгружает или перезатирает общий recovery-файл. Оговорка: `DeathAutoTrap` по умолчанию **выключен** (default `false`) — «воскрешение убитого в PvP» работает лишь на серверах, где админ его включил (фильтры `DAT*` сужают, какие смерти трапятся). Но сама recovery включена по умолчанию (`DisableRecovery=false`), и записи от **создания/сноса душ** (SoulGun/терминал) копятся в тот же общий пул независимо от death-auto-trap — поэтому кросс-тим `Recover Soul`/`Get Souls` актуален и без него. Дино должен быть прирученным/засоуленным (дикого так не поднять), и восстанавливается сохранённая **душа** на момент смерти/сноса, а не меш трупа. |
| 5 | Средняя | `SoulTerminalBuff_DS` — `Write Dino Bytes` (Net·Server) | Принимает клиентскую строку `File Name` и любое переданное `Dino` и вызывает `SaveGameToSlot` с этим именем как есть — без санитизации, без проверки владельца/админа/команды и (в отличие от `Get Souls`) без префикса `DinoStorage2/`. | Клиент пишет объект сейва `Bytes_DS` в произвольный слот в каталоге сейвов сервера — можно спамить файлами или столкнуться с другими слот-сейвами; захватываемое дино — любое, на которое клиент может сослаться. |
| 6 | Низкая | `SoulTerminalBuff_DS` — `Add Custom Buff` (Net·Server) | Клиентский `Buff Path` превращается в класс через `StringReferenceToClass` и применяется через `StaticAddBuff`; единственная защита — приведение к `PrimalBuff`. Тест `StartsWith "Mods/"` влияет только на подпись в меню, а не на то, применится ли бафф. | Произвольный путь к ассету баффа применяется к дино. Ограничено: цель (`Buffed Primal Dino`) задаётся только через admin-gated поток дебафф-пушки, так что дойти до неё нужен админ — скорее defence-in-depth, чем открытая дыра. |
| 7 | Низкая | `SoulTerminalBuff_DS` — `Trade Soul` (Net·Server) | В отличие от `Soul Options` и `Destroy Soul` (которые перепроверяют `TargetingTeam`), `Trade Soul` проверяет лишь что предмет существует и целевой инвентарь не полон. Полагается на то, что `Inventories`/`Viewing Inv` были проверены по команде при заполнении через `Get Terminals`. | Зазор TOCTOU: если валидированный набор удастся «протухнуть», предмет можно переместить в инвентарь, который игрок уже не разделяет. Низкая, т.к. набор фильтруется по команде на момент заполнения. |
| 8 | Низкая | `SoulTerminalBuff_DS` — `Set Terminal Text`, `Terminal Snapping`, `SoulGunWeap_DS` — `Terminal Mesh Toggle` | Работают с членом `Terminal` (последний использованный игроком терминал) без перепроверки команды в RPC. `Terminal Mesh Toggle` защищён только `LockTerminalMesh`. | Косметические/структурные правки (динамический текст, привязка, вариант меша) на терминале, которым игрок законно пользовался; ограничено командой, в основном грифинг терминала своего же племени. |
| 9 | Средняя | `SoulTerminalBuff_DS` — `Soul Options` (Net·Server); разворот — `DinoStorage2CCA` — `Spawn Dino DS` | Клиентский флаг `Neutered` пишется в `CustomDataStrings[3]` души без серверной перепроверки. Штатный UI (`SoulOptionsMU_DS`) держит необратимость кастрации односторонним латчем `Soul Options(…, BooleanOR(Was Neutered, New Neutered), …)` — если душа уже кастрирована, UI не может отправить `false`. RPC этот латч не применяет, а разворот `Spawn Dino DS` читает `[3]` → `Dino.bNeutered`. Гейт — `IsPlayerAllowedToCheat` ИЛИ своя команда. | Прямой вызов `Soul Options(Neutered=false)` на душе своего племени снимает кастрацию — при развороте дино выходит с `bNeutered=false` и снова разводится. Ломает необратимость кастрации: купленного/полученного кастрированного дино можно раскастрировать и развести, подрывая смысл продажи кастрированных особей. |

### Обход permission-гейта (сквозной паттерн)

Отдельно стоит выделить общий механизм за находками 2, 3, 6 и 8. Пункты меню терминала (`Bug Zapper`, `Newborn Auto Trap`, `Automation`, `Dynamic Text`, подменю `[Options]`/`[Admin]` и т.д.) добавляются в `SoulTerminalStructure_DS.BPGetMultiUseEntries` только при `AllowTribeGroupPermission(0, self)` **И** совпадении `TargetingTeam`, то есть видны лишь члену племени с нужным групповым правом на структуру. Это право **трайба/ранга**, а не админ сервера (`[Admin]` — лишь название подменю в UI мода; серверно-админский гейт `IsPlayerAllowedToCheat` и SteamID-бэкдор относятся к другим функциям — recovery, admin mode оружия). Но соответствующие серверные `NetServer`-RPC на баффе игрока `SoulTerminalBuff_DS` этот гейт **не перепроверяют**, поэтому прямой вызов события (не через UI) обходит его.

Подвержены (RPC без серверной проверки прав, хотя пункт меню закрыт правом трайба):

| Функция | Пункт меню | Находка |
| --- | --- | --- |
| `Set Bug Range` | Bug Zapper | 3 |
| `Set Newborn Range` | Newborn Auto Trap | 3 |
| `Apply Automation`, `Automation Settings` | Automation | этот раздел |
| `Set Terminal Text` | Dynamic Text | 8 |
| `Terminal Snapping` | [Options] | 8 |
| `Terminal Mesh Toggle` (`SoulGunWeap_DS`) | — | 8 |
| `Add Custom Buff`, `Save Buff`, `Debuff Dino` | buff-меню | 6 |
| `Starter Commit` | Starter Souls | 2 |

Ограничитель: указатель `Terminal` и выдача баффа ставятся в `BPTryMultiUse`, где на части веток есть серверная проверка `TargetingTeam`, так что навести RPC на терминал **чужого** племени в общем случае нельзя — обход бьёт внутри своей команды (игрок без нужного группового права/ранга всё равно может вызвать функцию, а значение `Range` вдобавок не клампится). С учётом этого severity паттерна: **средняя** для управляющих функций (радиусы, автоматизация, стартовые души) и **низкая** для чисто косметических (текст, привязка, меш) — то есть finding 8 уточняется от «нет re-check» к «обход tribe-permission-гейта», без повышения до критического, т.к. кросс-тимовый вектор закрыт проверками в `BPTryMultiUse`.

## Рекомендации

Первопричина везде одна: проверка живёт в UMG-виджетах, а серверные события вызываются напрямую. Каждый серверный RPC должен перепроверять на сервере, считая клиента враждебным.

**Автору мода (по приоритету)**

1. Удалить захардкоженный SteamID `76561198056637517` из `SoulTrapWeap_DS`, `SoulGunWeap_DS`, `SoulFinderWeap_DS` и `SoulTerminalStructure_DS` (находка 1). Статус админа должен приходить только из `IsPlayerAllowedToCheat` / `bIsServerAdmin`, а `DisableAdminMode` соблюдаться безусловно.
2. Добавить серверную проверку прав в `Starter Commit` — минимум `IsPlayerAllowedToCheat` (находка 2). Это самая широко эксплуатируемая обычными игроками дыра.
3. Клампить `Range` на сервере внутри `Set Bug Range` и `Set Newborn Range` до тех же 1–50 / 1–15, что в UI, до умножения на ×300 / ×38.25 (находка 3).
4. В `Recover Soul` и `Get Souls` заново выполнять проверку племени/прав, которую делает `BPServerHandleNetExecCommand`, и проверять `Dino Index` по границам массива; рассмотреть хранение recovery-данных по племенам, а не на весь мир (находка 4).
5. В `Write Dino Bytes` требовать админа, отклонять имена сейвов с разделителями пути или `..` и добавлять фиксированную папку-префикс так же, как делает `Get Souls` (находка 5).
6. Перепроверять `TargetingTeam` внутри `Trade Soul`, `Set Terminal Text`, `Terminal Snapping` и `Terminal Mesh Toggle` вместо доверия сохранённым членам `Terminal`/`Inventories` (находки 7, 8) и проверять `Buff Path` по белому списку в `Add Custom Buff` (находка 6).

**Временные меры для админов серверов**

- Нет INI, закрывающего бэкдор по SteamID (находка 1) либо дыры `Starter Commit`, радиусов и `Write Dino Bytes` — они достижимы независимо от настроек. Пока не выйдет исправленная сборка, надёжная мера одна: не запускать мод там, где это важно, либо запускать сборку, которую вы проверили сами.
- `DisableAdminMode=true` всё же уводит обычных игроков через `IsPlayerAllowedToCheat`, так что выставить его стоит, но он не останавливает захардкоженный SteamID.
- Следить за recovery/export `.sav`-файлами `DinoStorage2` и логами сервера на неожиданные сообщения `Starter Souls Created`, `Wrote Bytes To…` и recovery как признак атаки.

## Ограничения

- **Только статика.** Все находки получены чтением декомпилированного Kismet-байткода, а не вызовом RPC на работающем сервере. Утверждения о потоке управления и отсутствующих проверках подтверждены трассировкой достижимого кода каждого события (goto/if/push_flow и продолжения латентных таймеров) до «стока», но для сквозного подтверждения эксплуатируемости нужен живой клиент, реально вызывающий эти события.
- **Бэкдор по SteamID — только для автора.** Находку 1 может запустить лишь владелец `76561198056637517`; подделать её без компрометации Steam-аутентификации нельзя. Для оператора сервера это нераскрытый привилегированный бэкдор, а не эксплойт, открытый всем.
- **Покрытие декодера.** Парсеру потребовалась правка, чтобы читать опкод ARK `0x64` как 8-байтовую константу double (используется `CustomDataDoubles`); до этого функции, работающие с double-данными душ, обрывались на середине разбора. После правки все геймплейные блюпринты сошлись по `UStruct::BytecodeBufferSize` (785 функций, размер в памяти совпал). У нескольких косметических/материальных ассетов остаётся неразобранный 4-байтовый хвост, не влияющий на рассмотренную здесь логику.
- **Объём.** Рассматривалась только серверно-авторитетная логика (`NetServer`-события, обработчики net-exec команд и акторы терминала/структуры). Чисто клиентские/UMG-виджеты, материалы, меши и анимационные блюпринты читались лишь настолько, чтобы найти, кто вызывает серверные события. Поиск предметов по ID через `BPNetExecParams` (`IntParam1/2`) считался непрозрачным; может ли подделанный ID предмета сослаться на предмет чужого племени через `BPFindItemWithID`, не проверялось и заслуживает второго прохода.
- **Не проверено в игре.** Геймплейное влияние находок 3–5 (какой радиус терпит движок, что делает `SaveGameToSlot` со странным именем слота, как recovery-данные ведут себя между племенами) выведено из кода, а не измерено.
