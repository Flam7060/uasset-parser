# MAGA ORP (2031840245)

_2026-10-31_ · входит в [коллекцию MESA](MESA_Collection_3826240151.md)

## Сводка

Мод — клиентская половина серверного плагина **MAGA ORP** (offline raid
protection + PvP-таймер), тот же паттерн, что у Items+ Companion
(`Items_Companion_2564546455.md`): постройка/синглтон чисто декларативны,
решение и триггеры — в плагине (ArkServerApi/AngelScript, в Workshop его
нет). В моде **нет своего клиент→сервер RPC** (`WoolySetRadius`,
`DelayActivateShield`, `NetRefreshRadiusScale`, `updateShowRangeVisible` --
всё multicast, сервер→клиент) и **нет сетевого пути, которым клиент сам
взводит или снимает ПВП-таймер** -- функция, которая его ставит
(`MagaSingleton.APBTP`), не имеет флага `Net` вовсе, то есть физически не
RPC: её может вызвать только код, уже выполняющийся на сервере (сам плагин
через рефлексию, как `GetConfig`/`GetWeightConfig` у Items+).

**Что именно взводит таймер (нанесённый урон? полученный? по турели? по
игроку?) -- не определить статикой.** `APBTP` ни разу не вызывается ни в
одном из 91 ассета мода (ни `mod_search mode=xref`, ни `mode=text` не
находят вызывающего места) -- значит вызов приходит из внешнего кода
плагина, которого нет в Workshop-паке и, соответственно, в индексе
`ark-re`. Это тот же разрыв, что у Items+ (`GetConfig`/`GetWeightConfig`
плагин зовёт сам, в моде этих вызовов тоже нет).

На живом сервере ничего не проверялось.

## Объём и метод

Прочитаны ключевые ассеты (`MagaSingleton`, `Buff/Maga_PvpCd_Buff_C`,
`ORP/StorageBox_MagaShield`) через MCP `ark-re` (`asset_summary`,
`asset_function`, `mod_search` xref/text, `mod_audit`). Остальные ~88
ассетов -- сезонный ванильный хлам (`PrimalEarth/Structures/Halloween|
Valentine|Easter/...`), упакованный в мод по неясной причине, не
разбирался детально.

──────────────────────────────                          ─────────────────────

Внешняя логика плагина решает "это PvP?"             делает -- плагин ищет актор сам)
  (урон? турель? чья команда? -- неизвестно)
       │
       ▼
MagaSingleton.APBTP(Player, TimeToAdd)     ← НЕ RPC (флага Net нет), вызывается
  Player.HasBuff(Maga_PvpCd_Buff_C)?         прямым UFunction-рефлексией с сервера
    да  → GetBuff(...).UpdateTimeLeft(TimeToAdd)
    нет → StaticAddBuff(Maga_PvpCd_Buff_C_C, Player) → .UpdateTimeLeft(TimeToAdd)

Maga_PvpCd_Buff_C_C.UpdateTimeLeft(NewTime):
  если NewTime > остаток (GetTimeLeft) -- ResetBuffStart() + DeactivateAfterTime = NewTime
  (таймер только продлевается вверх, случайное укорачивание исключено)
  → ClientUpdateTimeLeft(NewTime)  -- Net|NetClient, реплицирует остаток владельцу для HUD

Структура `StorageBox_MagaShield` (родитель -- `BaseFuelBurner_GasOnly_C`,
то есть обычный контейнер с топливным инвентарём) -- щит-купол базы,
визуально не связан с PvP-таймером напрямую:

- `BPOverrideAllowStructureAccess` -- тривиальный passthrough
  (`return bIsAccessAllowed`), никакой скрытой логики доступа.
- `IsPushablePawn` / `Sign_EasterEgg.BPGetMultiUseEntries` -- два D6-находки
  `mod_audit` (решение по `TargetingTeam`), оба `server_reachable: false`,
  обычная игровая логика, не уязвимость.
- Нет серверных RPC вообще -- все клиентские функции (`WSetShieldRadius`,
  `wSetEnablePushEnableShield`, `wSetActivationTimeAndStart`) без сетевых
  флагов, то есть тоже вызываются плагином напрямую, не игроком.

## Находки

Эксплойтов не найдено -- `mod_audit` по всем шести детекторам даёт только
два D6 (низкая значимость, team-based, не server_reachable). Клиентского
RPC, которым можно было бы снять или подделать `Maga_PvpCd_Buff_C`, в моде
нет: взвод/продление таймера идёт исключительно прямым вызовом с сервера,
не сетевым пакетом, который можно подменить или повторить с клиента.

## Что это означает для нашего инструмента

Нельзя "обойти" ПВП-КД через память/RPC: сервер решает это полностью сам,
минуя сетевой стек, и клиент физически не участвует в взводе таймера --
ни подделать, ни подсмотреть момент взвода нашему коду недоступно. Если
нужно узнать точный триггер (урон от турели конкретно, или любой PvP-урон,
или что-то ещё) -- это вопрос к конфигу/коду плагина на стороне сервера,
не к ассетам мода; статический разбор Workshop-пакета этого не покажет.

## Ограничения

- Код плагина MAGA ORP недоступен (не в Workshop) -- всё, что зависит от
  его поведения (условие взвода `APBTP`, длительность `TimeToAdd`), не
  проверено и не может быть проверено этим инструментарием.
- Сезонный хлам в паке (`PrimalEarth/Structures/Halloween|Valentine|Easter`)
  не разбирался -- не относится к ORP/PvP-функциональности.

## Что делает

Клиентская часть серверного плагина **MAGA ORP** (offline raid protection). Описание Workshop: «Does nothing except being a structure». Даёт постройку-генератор щита: купол, визуализация радиуса, эффекты зарядки. Логику ORP (когда щит активен, кто не может наносить урон) решает плагин.

## Как сделано

- `PrimalItemStructure_MagaORP` + `EngramEntry_MagaORP`. Сама постройка — `StorageBox_MagaShield` с мешем генератора и сферами `Maga_TekShield*` / `MAGA_Show_Range*`.
- `MagaSingleton` — серверный синглтон (`ServerExtraWorldSingletonActorClasses`), через него плагин управляет щитами.
- У постройки нет `NetServer` RPC, только multicast (`WoolySetRadius`, `DelayActivateShield`, `NetRefreshRadiusScale`, `updateShowRangeVisible`). Их вызывают «внешние» функции `WSetShieldRadius`, `wSetEnablePushEnableShield`, `wSetActivationTimeAndStart`, предназначенные для плагина.
- `Buff/Maga_PvpCd_Buff_C` — PvP-кулдаун: client RPC `ClientUpdateTimeLeft` показывает оставшееся время.
- В `PrimalEarth/` лежат копии сезонных ванильных ассетов (Valentine's, Easter, Halloween) — их зачем-то упаковали в пакет.
- Ini-ключей нет: настройки у плагина.
